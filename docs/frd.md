## 1. 목적과 범위

N-Pick은 뉴스 영상에서 필요한 장면을 찾고, 검색 중 발견한 오류를 검수자가 교정하는 서비스다. 편집기자가 사용할 장면을 더 쉽게 찾도록 하면서 편집·검수에 드는 전체 업무량을 늘리지 않는 것이 목표다.

기본 흐름은 다음과 같다.

```
로그인 → 영상 등록·처리 → 장면 검색 → 결과·미리보기 확인
                                    ↓
                              이상해요 신고
                                    ↓
                       변경안 작성 → 자동 재검색
                                    ↓
                       검수자 확인 → 확정·검색 반영
```

### 1.1 이번 버전에 포함하는 것

| 영역 | 제공 기능 |
| --- | --- |
| 계정 | 미리 등록한 계정의 아이디·비밀번호 로그인, 로그아웃, 역할별 접근 제한 |
| 영상 | 방송분·자료 영상 등록, 자막·대본·날짜 입력, 처리 상태 확인·재시도 |
| 분석 | 장면 분할, 키프레임·대표 이미지, 화면 글자 읽기, 대사 추출, 설명·태그 생성 |
| 검색 | 한국어 검색어 해석, 단어·텍스트 의미 검색, 조건에 따른 순위 계산, 잘못된 결과 제외 |
| 결과 | 장면 카드, 촬영일·방송일, 검색 근거·미검증 표시, 구간 미리보기 |
| 신고·교정 | 결과별 신고, 태그 교정, 해석 패턴 교정, 특정 검색의 장면 제외 |
| 검증 | 변경안을 임시 적용한 자동 재검색, 검수자 확인 후 확정 |
| 기록 | 처리·검색·신고 기록, 교정 근거, 검증한 내용, 적용 규칙과 전후 해석 |

사전 등록 계정 로그인과 방송분·자료 영상 등록은 v3.0 작성 중 사용자가 포함하기로 확인했다.

### 1.2 이번 버전에 추가하지 않는 것

- 회원가입, 비밀번호 찾기, 별도 회원관리 화면.
- 검색 전 모든 영상·장면을 사람이 승인하는 전수검수.
- 신고와 무관한 자유 태그 편집, 다른 클립을 묶은 일괄 교정.
- OCR 원문·자막·캡션·샷 유형의 직접 편집. 태그로 표현된 값의 교정은 포함한다.
- 검색 결과가 0건인 경우의 별도 신고 기능.
- 신고만으로 이루어지는 자동 승인, 모델 재학습, 개인화, 전체 순위 가중치 자동 변경.
- 사건 목록 관리·영상의 사건 배정 기능. 사건명 태그는 사용하지만 별도 사건 관리 시스템은 만들지 않는다.
- 유사도 기반 규칙 매칭, 검색 해석 캐시, 별도의 LLM 질의 재작성 단계, 전역 동의어 관리 화면.
- 이미지 임베딩 검색, 객체 탐지, 화자 식별, 영상 편집·편집 도구 내보내기, MAM 실연동.
- 다단계 승인, 모든 규칙 켜기·끄기의 감사 이력, 별도 색인 세대·outbox·자동 복구 플랫폼.
- 군중 밀도(밀집도)의 태그·검색. v3.1 에서 범위 밖으로 확정했다. §11 참고.
- 영상별 사용권·외부 전송 허용 여부의 DB 저장. 전송 금지 요구 자체는 §6.4 로 유지한다. §11 참고.

현재 ERD에 없다는 이유만으로 기존 요구를 삭제하지 않는다. 대응이 불명확한 항목은 §9에 따로 적는다. 문서 분량을 줄이는 것과 기능 범위를 줄이는 것은 구분한다.

### 1.3 문서를 읽는 방법

- **완료 기준**: 해당 기능이 구현됐는지 확인할 조건이다.
- **조건부**: 외부 색인처럼 해당 구성을 실제로 사용할 때만 필요한 사항이다.
- **확인 필요**: 문서 작성은 진행할 수 있지만, 해당 구현·실행 전에 결정해야 하는 사항이다.
- 기능은 이 문서, 컬럼·관계는 현재 ERD, 교정의 상세 실행 규칙은 피드백 루프 최종 설계안을 기준으로 본다.
- 과거 PRD의 범위를 새로 섞지 않는다. v2.2의 오래된 결정표가 이번 확정 변경을 다시 취소하는 근거가 되지는 않는다.

## 2. 사용자와 권한

| 사용자 | 할 수 있는 일 | 할 수 없는 일 |
| --- | --- | --- |
| 편집기자 `editor` | 검색, 근거·미리보기 확인, 이상해요 신고 | 영상 등록, 태그·규칙 변경, 검수 확정 |
| 검수자 `reviewer` | 영상 등록·처리 확인·재시도, 신고 검수, 교정 후보 작성·검증·확정, 규칙 사용 중단 | 신고와 무관한 전수 편집, 명시적 사용자 필터를 임의로 바꾸는 교정 |

### F-01. 로그인과 접근 제한

**사용자:** 편집기자·검수자.

1. 사용자는 미리 등록된 아이디와 비밀번호로 로그인한다.
2. 시스템은 계정에 저장된 역할에 맞는 기능만 허용한다.
3. 로그아웃하면 기존 로그인으로 보호된 기능을 계속 사용할 수 없어야 한다.
4. 로그인 실패는 한국어로 안내하고, 비밀번호나 계정의 민감 정보를 응답에 포함하지 않는다.
5. 인증은 발급 후 30분에 만료되고 일반 요청으로 연장하지 않는다. 별도 refresh로 최초 로그인부터 최대 8시간까지 인증을 재발급하며, refresh로 이 기한을 늘리지 않는다. 인증과 refresh는 서버 재시작에도 보존하고 로그아웃 시 모두 폐기한다. (2026-09-19 사용자 확정)

**완료 기준:** 비밀번호를 평문 저장하지 않는다. 편집기자가 검수 API를 직접 호출해도 거부된다. 등록자·신고자·검수자는 서버가 로그인 계정에서 기록하며 클라이언트가 지정한 사용자 ID를 신뢰하지 않는다.

로그인 제공이 공개 서비스·다중 사용자 운영 품질 보장을 뜻하지는 않는다. v2.2의 로컬·데스크톱 중심 검증 범위는 유지한다.

## 3. 영상 등록과 처리

### F-02. 영상 등록

**사용자:** 검수자.

| 입력 | 규칙 |
| --- | --- |
| 영상 파일 | 한 등록 요청당 파일 1개. 선택 시 확장자·용량과 실제 MP4/MOV 컨테이너 헤더를 검사하고, 서버에서 길이·실제 재생 가능 여부를 최종 검사 |
| 영상 종류 | 방송분 `broadcast` 또는 자료 영상 `archive` |
| 제목 | 선택 입력, 최대 50자(UTF-16 길이 기준). 비어 있으면 표시용 파일명을 사용할 수 있으나 사실 정보로 간주하지 않음 |
| 방송일 | 방송분에 선택 입력. 1950년 1월 1일부터 오늘(Asia/Seoul)까지 선택·입력 가능. 자료 영상에는 방송일 태그를 붙이지 않음 |
| 촬영일 | 두 영상 종류 모두 선택 입력. 1950년 1월 1일부터 오늘(Asia/Seoul)까지 선택·입력 가능. 방송일과 서로 복사하지 않음 |
| 자막 | 선택 입력. 확장자뿐 아니라 UTF-8 내용과 SRT·VTT 또는 승인된 시간 구간 JSON 구조를 검사하고 시간 정보가 있는 자막을 우선 사용 |
| 일반 대본 | 선택 입력. TXT에는 고유 헤더가 없으므로 UTF-8 내용·바이너리 제어 문자·다른 문서 형식 헤더를 검사한다. 시간 정보가 없으면 영상 전체 참고 자료로 사용 |
| 사용권·외부 처리 확인 | 기존 보호 요구 유지. 미확인 자료를 외부 AI에 보내지 않음. 증빙·저장 경로는 §9에서 확정 |

등록하면 영상과 처리 작업을 만들고 처리 화면에서 진행 상황을 확인할 수 있다. 같은 파일의 중복 등록을 검사한다. 동일 요청의 재전송과 사용자가 요청한 재처리는 구분한다.

방송일·촬영일은 서비스 디자인의 단일 날짜 달력으로 선택하며 월·연도 이동, 키보드 조작과 날짜 지우기를 지원한다. 날짜 선택은 즉시 반영하고 Escape·바깥 클릭·포커스 이탈로 닫는다. 방송일은 촬영일 이전을, 촬영일은 방송일 이후를 선택할 수 없다. 직접 입력은 YYYY-MM-DD 형식과 실제 달력 날짜를 검사한다. 선택한 영상의 파일명·용량·선택 상태는 파일 선택 영역 안에 표시하고 별도 파일 행을 만들지 않는다. `파일 선택`은 유지하며 재선택 시 영상 정보만 바뀐다. 내용 검사 중에는 등록을 막고, 연속 선택 시 마지막 파일의 검사 결과만 적용한다. 파일 선택 전에는 중립 배경·점선 테두리, 선택 후에는 초록 배경·실선 테두리와 선택 표시로 구분한다. 일반 동작은 파랑 계열을 사용하고 빨강·분홍 계열은 오류 상태에만 사용한다.

**실패 시:** 잘못된 입력은 해당 항목 근처에 설명하고 입력을 유지한다. 파일 저장·작업 등록 실패를 등록 성공으로 표시하지 않는다.

**완료 기준:** 날짜를 모두 비워도 등록할 수 있다. 자료 영상에 방송일을 입력하면 명확히 거부한다. 동일 요청 재전송으로 영상·작업이 중복 생성되지 않는다. 사용자가 서버의 임의 경로를 입력해 파일을 읽게 할 수 없다.

### F-03. 장면 분석과 처리 상태 확인

**사용자:** 검수자. **실행:** 시스템.

| 처리 | 만들어야 하는 정보 |
| --- | --- |
| 장면 분할 | 장면별 시작·종료 시각 |
| 프레임 추출 | 장면의 복수 키프레임과 결과 카드에 쓸 대표 이미지 |
| 영상 설명 생성 | 장면 설명, 샷 유형, 태그 후보 |
| 화면 글자 읽기(OCR) | 읽은 원문, 신뢰도, 위치, 해당 키프레임 |
| 자막·음성 처리 | 제공 자막·CC를 우선 사용하고 없는 구간은 음성인식으로 보완 |
| 장면별 대사 연결 | 시간상 겹치는 대사와 겹친 구간 |
| 태그 추출 | 인물·장소·날짜 등 태그와 근거 |
| 검색 준비 | 검색용 토큰·텍스트 임베딩·필요한 검색 데이터 |

시스템은 처리 단계와 성공·실패·생략 여부를 기록한다. 검수자는 진행 단계, 실패 이유, 재시도 가능 여부를 볼 수 있다. 한 영상의 실패 때문에 다른 영상의 처리를 모두 중단하지 않는다.

키프레임은 장면마다 고정된 장 수로 뽑지 않는다. 장 수는 장면 안의 변화량으로 정해 정적 장면은 적게, 동적 장면은 많게 추출한다. 변화량 척도는 장면 분할이 쓰는 content score 와 통일할 것을 권고한다. 사용한 임계값과 선택 파라미터는 처리 버전에 포함해, 어떤 설정으로 뽑은 프레임인지 나중에 확인할 수 있어야 한다. 후보 수·변화량 임계·장면당 평균 장 수의 구체값은 이 문서에서 정하지 않고 §11 에 따라 실측으로 정한다. 이 요구는 v2.2 의 처리 요구사항에서 왔으나, §10.2 대로 옛 요구사항 ID 를 같은 의미로 재사용한다고 가정하지 않는다.

OCR은 추출한 키프레임을 대상으로 수행한다. 작은 글자를 읽을 때는 축소된 대표 이미지 대신 원본 해상도의 프레임을 사용한다. 중복 글자를 묶어도 원본 관측과 프레임으로 돌아갈 수 있어야 한다. AI 출력은 정해진 형식으로 검사하고, 형식이 잘못된 출력을 정상 데이터에 부분 적용하지 않는다.

VLM은 키프레임과 해당 장면의 OCR·최종 채택 대사를 종합하여 캡션·태그를 생성한다. 화면에서 관찰되는 내용과 텍스트가 설명하는 맥락의 관계를 해석해 장면을 구체적으로 설명한다. 앵커의 소개·과거 자료 화면·타 지역 비교를 현재 화면의 인물·촬영 장소·시점과 혼동하지 않는다. VLM은 OCR 및 장면 대사 연결 이후 실행하며, 없는 텍스트는 사용 가능한 입력으로 보완하고 임의 생성하지 않는다.

제공 자막과 내장 CC가 겹치면 제공 자막을 우선한다. 일반 대본을 모든 장면의 실제 발화처럼 복제하지 않는다. 영상 전체의 기본 대사 출처와 개별 장면의 실제 출처가 다를 수 있음을 기록한다.

VLM·OCR·음성인식 중 하나가 실패해도 나머지 결과를 사용할 수 있으면 처리를 계속한다. 다만 재생 가능한 영상·장면 구간·대표 이미지·저장된 결과와 하나 이상의 사용 가능한 검색 텍스트를 확보하지 못하면 검색 가능으로 표시하지 않는다.

**완료 기준:** 장면의 OCR·채택 대사가 VLM 입력에 연결되고 다른 장면·보관 전용 대사가 혼입되지 않는다. 화면과 텍스트 맥락을 구분하는 사례 및 텍스트 누락을 검증한다. 사전검수 없이 정상 처리된 영상이 검색된다. 실패한 단계와 빠진 기능을 확인할 수 있다. 재시도가 성공 산출물을 중복 생성하지 않는다. 장면 구간은 시작 시각 포함·종료 시각 제외로 해석한다.

### F-04. 태그와 근거 관리

태그는 영상·장면의 검색 가능한 속성을 나타낸다. 같은 값을 표시할 이름과 검색용 정규화 값으로 나누어 저장한다.

| 종류 | 현재 ERD의 태그 유형 |
| --- | --- |
| 인물·기관·장소 등 | `person`, `organization`, `location`, `facility`, `keyword`, `event` |
| 분류 | `season`, `weather`, `scene_type` |
| 날짜 | `filmed_date`, `broadcast_date` |
- 검색용 정규화 값(`tag.match_value`)은 표시 이름에 유니코드 NFKC 를 적용하고 **보이지 않는 문자를 제거해** 만든다. 공백뿐 아니라 ZWSP·BOM·soft hyphen 같은 폭 없는 문자도 지운다 — 이름에 SPACE 가 붙어도 유니코드 공백이 아니라 NFKC 가 건드리지 않고, 붙여넣기·OCR 로 흔히 섞여 들어와 같은 값을 두 행으로 가른다. 이모지를 조립하는 ZWJ·ZWNJ 는 의미를 가르므로 남긴다.
- 제거 뒤 NFKC 를 한 번 더 적용한다. 문자를 지우면 그것이 막고 있던 결합이 성립해, 다시 접지 않으면 결과가 정규형이 아니게 된다.
- **명시 필터 값도 같은 규칙을 쓴다.** 필터 값은 자유 텍스트가 아니라 태그·enum 이고 태그 값에 정확 일치로 맞춰지므로, 규칙이 갈리면 같은 태그를 찾아오는 두 표기가 다른 검색 지문을 갖는다. 질의(`normalized_query`)는 형태소 분석 입력이라 공백이 의미를 가지므로 이 규칙을 타지 않는다 — 정규화 형태는 「정확 일치 키」와 「토큰화 질의」 둘이다.
- 대소문자는 보존한다. casefold 를 걸지 않는다 — 태그 값은 대소문자가 의미를 가를 수 있다. 명시 필터의 정규화에서 casefold 를 뺀 것과 같은 이유다.
- 동의어·별칭은 확장하지 않는다. 다른 이름으로 같은 대상을 가리키는 문제는 F-05 의 검색어 해석이 담당한다.
- 날짜는 실제 달력에 존재하는 `YYYY-MM-DD` 값으로 검사한다. `filmed_date`가 촬영일이다.
- 영상 전체 태그는 해당 영상의 장면에 상속된다. 장면 태그는 해당 장면에만 적용된다.
- VLM이 OCR·대사를 활용한 경우 해당 원본 관측·대사 구간 참조를 보존한다. 생성 출처는 계속 VLM이며 텍스트의 출처로 바꾸지 않는다.
- 태그 하나에 여러 근거가 붙을 수 있다. 값만 저장하지 않고 출처와 확인 가능한 근거 위치를 연결한다.
- 사용자 입력·원본 정보·CC·OCR 등 관측 근거와 ASR·VLM·규칙의 추정 근거를 구분한다. AI의 높은 신뢰도만으로 검증된 사실로 올리지 않는다.
- OCR 신뢰도와 원본 문맥을 확인하지 않고 화면의 날짜 문자열을 방송일·촬영일로 간주하지 않는다.
- 현재 ERD의 출처 중심 정책에 맞춰 ASR·VLM·일반 추론 규칙은 기본 미검증으로 처리한다. 사람의 승인 판단은 별도로 남긴다.
- 샷 유형은 태그가 아니라 `scene.shot_type`이다. 값은 `anchor`, `interview`, `b_roll`, `unknown`을 사용한다.

**완료 기준:** 태그의 출처를 확인할 수 있고 불확실한 값은 미검증으로 표시된다. 사람 판단과 자동 추출값을 혼동하지 않는다. 계절·날씨·장면 유형·날짜를 별도 컬럼으로 중복 관리하지 않는다. 같은 값의 다른 표기가 서로 다른 태그로 저장되지 않는다.

## 4. 검색과 결과 확인

### F-05. 검색어 해석과 검색 실행

**사용자:** 편집기자. 검수자도 신고를 검증하기 위해 검색한다.

방송일·촬영일 검색 범위는 1950년 1월 1일부터 오늘(Asia/Seoul)까지만 허용한다(S15P21A501-287). 달력의 허용 범위 밖 날짜·월·연도와 키보드 이동을 제한하고, 직접 입력한 URL의 범위 위반도 안내와 함께 검색을 차단한다. 사이드바의 `기간 설정` 한 항목에서 방송일·촬영일 기준을 드롭다운으로 선택하며, 기준 드롭다운은 채움색 없이 굵은 글자로 표시하며 오른쪽에 최근 1·2·3년 버튼을 간격을 두고 배치한다. 기준별 초안과 기존 조건을 독립적으로 유지하고 적용 시 함께 반영한다. 초기화는 선택한 기준만 즉시 비우고 날짜 패널과 사이드바를 열어 둔다. 닫기는 기록 패널과 같은 왼쪽 화살표 버튼을 사용하며 별도 취소 버튼은 두지 않는다. 선택 불가 기간에는 기본 커서를 사용하고 클릭하면 `해당 기간은 선택할 수 없어요` 툴팁을 표시한다. 사이드바 각 메뉴는 hover·키보드 포커스 시 서비스 디자인의 툴팁에 `기간 설정`, `이전 검색 기록`, `문의 사항`을 표시한다. 날짜 팝업은 사이드바가 펼쳐져 있을 때만 표시하며 다른 메뉴의 오른쪽 끝을 눌러도 사이드바를 접지 않고 해당 메뉴로 전환한다. 기간 작업 완료·닫기·바깥 클릭·탐색 영역 밖으로 포커스 이탈 시 함께 닫는다. 선택 범위의 시작·끝과 주 경계에는 살짝 둥근 모서리를 적용하고 기록 목록은 서비스 색상의 얇은 스크롤바를 사용한다. 달력에서 시작일·종료일을 역순으로 선택하면 즉시 이른 날짜를 시작일로, 늦은 날짜를 종료일로 재정렬하고 적용 시 반영한다. 시작일·종료일 누락, 존재하지 않는 날짜와 직접 입력한 URL의 역순 범위 검증은 유지한다. 오늘은 마운트 이후에 주입하고 최근 기간의 기준일도 같은 한국 날짜를 사용한다.

1. 사용자가 한국어 검색어와 선택 필터를 입력한다. 이전 검색이나 대화를 몰래 이어받지 않는다.
2. 시스템은 원문을 보존하고 검색어·필터를 일관된 규칙으로 정규화한다.
3. AI 해석기는 날짜 범위, 사건명, 인물·기관·장소·시설, 관련 검색어, 검색 의도를 구조화한다.
4. 해석 패턴에 맞는 승인 규칙을 적용한다. 사용자가 직접 입력한 필터는 AI나 규칙이 바꿀 수 없다.
5. 단어 검색(BM25)을 기본으로, 텍스트 의미 검색과 날짜·태그 등 관련 정보를 결합해 후보를 찾고 순위를 정한다.
6. F-06의 제외 기준과 승인된 장면 제외 규칙을 적용한 뒤 한 페이지당 최대 10개 결과를 반환한다. 남은 유효 후보가 더 있으면 사용자는 「더보기」로 다음 페이지(다음 실행)를 요청할 수 있고, 응답의 `has_next`가 이를 알린다. 각 페이지는 새 실행이며 결과 구간만 다르다 — 과거 결과를 이어받지 않는다(§7.2).
7. 검색어, 실제 해석, 후보·제외 사유·결과, 사용 설정과 규칙을 기록한다.

같은 검색을 구분하는 지문값에는 정규화한 검색어·명시 필터·정규화 버전이 포함된다. 기존 고정 해석·장면 제외는 이 조건으로 조회하고 전체 정규화 값도 비교한다. 신규 패턴 규칙은 검색어 지문 일치가 아니라 AI 원본 해석의 조건으로 판정한다.

사용자가 직접 명시한 내용과 AI가 추정한 내용을 구분한다. 원문에서 확인되지 않는 인물·사건·날짜를 사용자의 명시 조건으로 표시하지 않는다. 관련 검색어 확장은 해석 출력 안에서 처리하며, 결과가 적다는 이유로 별도 LLM 재작성 요청을 추가하지 않는다.

기존 `pin_parse` 활성 규칙이 실제로 사용 중이면 해당 조건에서 AI 호출을 생략하는 호환 경로를 유지한다. 새 해석 교정은 `patch_parse`로 작성하며, 구 규칙이 없으면 호환 전환 작업을 만들지 않는다.

**순위 원칙:** BM25와 텍스트 의미 검색의 순위 결합(RRF)은 v2.2에서 유지한다. 관련 없는 B-roll이나 최신 영상이 관련성이 높은 장면보다 무조건 앞서지 않게 한다. 정보가 없는 항목에 가점을 주지 않고, 같은 개체를 중복 계산하지 않는다. 일반 대본은 기본 단어 검색 대상에서 제외한다.

**구조화 축 점수:** 축별 점수는 그 축에서 일치한 고유 조건 수를 활성 고유 조건 수로 나눈 값이고, 전체 점수는 활성 축의 가중평균이다. 값이 없거나 불일치한 활성 축도 0점으로 분모에 남긴다 — 분모에서 빼면 정보가 없는 항목에 가점을 주는 것과 같다. 고유 조건은 (태그 종류, 검색용 정규화 값) 으로 세며 분자·분모에 같은 기준을 적용한다. 종류가 다르면 이름이 같아도 다른 조건이다 (기관과 시설). 활성 조건이 하나도 없으면 0점이다. 축 가중치 값은 §11.1 의 실행 환경 설정값이므로 실측 전까지 확정하지 않는다.

**완료 기준:** 표현이 다른 검색에도 조건이 맞는 해석 규칙이 적용된다. 조건이 맞지 않으면 적용하지 않는다. 태그 교정이 후보 추출·필터·점수·설명에 일관되게 반영된다. 검색 설정이 달라지면 사용한 설정과 버전을 구분할 수 있다.

### F-06. 명백히 잘못된 결과 제외

불확실한 정보를 모두 제거하는 것이 아니라, 명시 조건과 검증된 정보가 분명히 충돌하는 경우만 제한한다.

| 상황 | 동작 |
| --- | --- |
| 명시한 날짜와 같은 종류의 검증된 날짜가 일치 | 관련성 계산에 사용 |
| 날짜·사건명 정보가 없거나 미검증 | 그 이유만으로 제외하지 않고 미상·미검증 표시 |
| 명시한 날짜와 같은 종류의 검증된 날짜가 충돌 | 결과 제외 |
| 사건명 충돌 | 근거가 있고 승인된 사건 충돌 판정 규칙이 있는 경우에만 자동 제외 |
| 인물·기관·장소·시설의 불일치 | 그 이유만으로 강제 제외하지 않고 관련성 점수에 반영 |
| AI가 추정한 조건만 충돌 | 강제 제외 근거로 사용하지 않음 |
| 승인된 특정 장면 제외 규칙 | 같은 검색어·필터 조건에서 해당 장면 제외 |

별도 표현 없이 연도·날짜만 입력하면 방송일 기준으로 해석한다. 촬영 의미를 명시하면 촬영일 기준으로 해석한다. 두 날짜를 서로 대체하지 않는다. 자료 영상의 방송일 부재도 검증된 날짜 충돌로 취급하지 않는다.

사건명 태그가 있다는 사실만으로 서로 다른 사건이 배타적이라고 판단하지 않는다. 승인된 사건 충돌 규칙이 없으면 해당 자동 제외를 사용하지 않는다. 해석 교정 규칙과 사건 충돌 판정 규칙은 같은 기능이 아니다.

**완료 기준:** 제외한 결과를 다시 채워 넣지 않는다. 다음 유효 후보가 있으면 원래 순서를 유지해 보충하고, 부족하면 10개 미만을 반환한다. 실제 반환 수와 제외 이유를 기록한다. 검색 실패를 결과 0건으로 위장하지 않는다.

### F-07. 결과 카드와 미리보기

| 영역 | 제공 내용 |
| --- | --- |
| 장면 카드 | 대표 이미지, 영상 제목, 장면 시작·종료, 샷 유형 |
| 날짜 | 방송일·촬영일을 따로 표시. 미상과 미검증 구분 |
| 검색 근거 | 일치한 설명·OCR·대사·태그와 출처 |
| 상태 | 검수 규칙 적용, 일부 기능 누락, 기록 저장 실패 등 필요한 안내 |
| 미리보기 | 원본 영상의 해당 장면 시작부터 재생, 장면 구간·현재 위치, 구간 다시 재생 |
| 신고 | 각 결과의 이상해요 버튼 |

미리보기는 기본적으로 장면 끝 이후에도 계속 재생하고 장면 경계를 표시한다. 영상 내 이동과 부분 재생 요청을 지원한다. 파일 누락·재생 불가·구간 이동 실패는 한국어로 안내한다.

**완료 기준:** 카드에서 선택한 장면 시작 지점으로 재생된다. 미리보기에서도 근거·미검증 상태를 확인할 수 있다. 서버 절대 경로를 노출하지 않는다.

## 5. 신고, 검수와 교정

### F-08. 이상해요 신고

**사용자:** 편집기자.

1. 결과의 이상해요 버튼을 누른다. 설명은 선택 입력이다.
2. 서버는 저장된 결과에서 검색어·필터·당시 해석·선택 장면·순위·근거를 찾아 연결한다.
3. 신고를 접수하고 접수 완료를 알린다. 사용자가 같은 정보를 다시 입력할 필요는 없다.

신고 접수만으로 결과·태그·규칙·전체 검색 순위를 바꾸지 않는다. 결과가 저장되지 않았거나 유효하지 않으면 신고할 수 없는 이유를 표시한다. 검증 전용 검색 결과를 일반 편집기자에게 노출하거나 일반 신고 대상으로 사용하지 않는다.

**완료 기준:** 설명 없이도 신고된다. 같은 제출 요청의 재전송은 중복 접수되지 않는다. 이후 같은 문제가 다시 발생하면 별도 신고할 수 있다. 다른 검색의 결과·장면을 섞은 요청을 거부한다. 신고 내용은 외부 티켓 서비스로 보내지 않는다.

### F-09. 신고 검수와 처리 결과

**사용자:** 검수자.

목록에서 접수 상태·시각·검색어·장면을 확인하고, 상세 화면에서 당시 결과와 현재 태그·근거를 비교한다. 검수 시작 시 담당자를 기록한다.

| 진단·선택 | 처리 결과 | 해야 할 일 |
| --- | --- | --- |
| 태그가 잘못됨 | `tag_correction` | F-10의 태그 변경안 작성 |
| 검색어를 잘못 해석함 | `patch_parse` | F-11의 해석 규칙 후보 작성 |
| 태그와 해석 모두 잘못됨 | `patch_parse` | 두 변경안을 함께 검증. 태그 교정 기록도 연결 |
| 특정 검색에서 장면 제외 필요 | `exclude_scene` | 신고 장면의 제외 후보 작성 |
| 문제없음·조치 불필요 | `no_action` | 판단 이유를 기록하고 종료 |
| 현재 범위에서 처리하기 어려움 | `deferred` | 대상과 보류 이유를 기록하고 종료. 교정 완료로 표시하지 않음 |

기존 `pin_parse` 처리 결과와 기록은 보존하지만 새 해석 교정 화면은 패턴 교정을 기준으로 한다.

**완료 기준:** 교정은 F-12·F-13을 거쳐야 완료된다. 문제없음·보류는 교정 후보를 만들지 않으며 불필요한 검증 검색을 요구하지 않는다. 어느 경우에도 담당자·이유·처리 결과를 확인할 수 있다. 보류한 문제를 자동 개선됐다고 알리지 않는다.

### F-10. 태그 교정

**사용자:** 검수자. **대상:** 신고 장면과 그 장면이 속한 클립.

| 작업 | 동작 |
| --- | --- |
| 추가 | 필요한 태그를 승인하는 판단 추가 |
| 반려 | 잘못된 태깅을 사용하지 않도록 판단 추가 |
| 교체 | 기존 태깅 반려와 올바른 태깅 승인을 함께 처리 |
| 복원 | 특정 값을 다시 승인하거나, 사람의 개입을 해제해 원본·상속 근거로 복귀 |

| 적용 범위 | 영향 |
| --- | --- |
| 해당 장면 | 해당 장면만 교정. 클립 전체 태그와 다른 장면은 유지 |
| 클립 전체 | 클립 태그를 상속하는 장면에 반영. 기존 장면별 검수 예외는 유지 |

클립에서 상속된 태그라도 해당 장면에만 부적절하면 장면별 예외로 반려·교체할 수 있어야 한다. 같은 태그의 판단은 **장면의 최신 사람 판단 → 클립의 최신 사람 판단 → 일반 근거** 순으로 적용한다.

원본 근거와 과거 판단을 덮어쓰거나 삭제하지 않는다. 새 AI 근거가 사람의 유효한 반려를 뒤집지 않는다. 개입 해제(`withdrawn`)는 그 범위의 과거 승인을 되살리는 동작이 아니라, 그 범위에 사람 판단이 없는 것처럼 원본·상속을 다시 평가하는 동작이다.

날짜처럼 한 값으로 정해야 하는 속성의 서로 다른 태그가 충돌하면, 반려할 값과 남길 값을 명시한다. 교체 취소 시에도 이전값·새 값 양쪽의 후속 교정을 확인한다. 한 장면을 고치려고 공용 태그 사전의 의미를 바꾸지 않는다.

**완료 기준:** 네 작업과 두 적용 범위를 모두 지원한다. 같은 교정이 다른 검색에도 반영된다. 변경 범위와 이전값·변경값을 확인할 수 있다. 사람 판단에는 임의의 신뢰도 1.0을 넣지 않고 원인 신고를 연결한다.

### F-11. 해석 패턴 교정과 장면 제외

**해석 교정:** AI가 만든 원본 해석에서 조건을 확인하고, 검수자가 정한 변경만 직접 적용한다.

예: 어떤 공장명이 장소로만 해석되어 사건 검색을 놓쳤다면, 해당 패턴을 찾아 장소 항목을 제거하고 원본 항목의 값을 사건명으로 옮기는 규칙을 만든다. 문장이 비슷하다는 이유가 아니라 **해석 조건이 맞는 경우**에 적용한다.

- 대상은 사건명, 인물·기관·장소·시설, 검색 의미어, 날짜 조건, 검색 의도다.
- 변경은 값 설정·해제, 목록 항목 추가·제거로 제한한다. 필요한 원본 항목의 값을 재사용할 수 있다.
- 명시적 사용자 필터, 권한, 점수 가중치, 규칙 활성 상태는 패치하지 않는다.
- 임의 JSON 편집·스크립트·정규식·외부 호출은 지원하지 않는다. 허용 조건·연산의 상세는 최종 설계안 §7을 따른다.
- 모든 조건은 같은 AI 원본 해석에서 한 번 판정한다. 앞 규칙의 결과로 다시 조건을 찾거나 LLM을 재호출하지 않는다.
- 독립 규칙은 함께 적용한다. 충돌 그룹은 건너뛰고 나머지는 적용하며 사유를 기록한다. 임의의 마지막 규칙이 이기는 방식은 쓰지 않는다.
- 한 규칙의 일부만 성공한 상태를 남기지 않는다. 적용 후 해석이 유효하지 않으면 마지막 유효 상태로 되돌린다.
- 조건·본문 변경은 새 규칙 ID로 작성해 검증 후 교체한다. 기존 본문·과거 적용 기록은 유지한다.

**장면 제외:** 기존 `exclude_scene`을 유지한다. 신고가 발생한 검색어·필터 조건에서 신고 장면을 제외한다. 다른 조건의 검색이나 다른 장면으로 자동 확대하지 않는다. 태그·해석 오류의 교정을 대신하는 만능 조치로 사용하지 않는다.

**사용 중단:** 검수자가 규칙을 끄면 이후 검색에서 적용하지 않는다. 다시 사용하려면 현재 조건에서 검증하고 승인한다. 과거 실행 결과는 바꾸지 않으며, 모든 켜기·끄기의 수행자·사유·시각을 완전히 복원하는 기능은 제공하지 않는다.

**완료 기준:** 다른 표현의 질의에도 동일 해석 패턴이 맞으면 교정되고, 비슷한 문장이어도 조건이 다르면 적용되지 않는다. 독립 규칙 두 개 이상을 적용할 수 있다. 충돌·실패·비호환과 단순 조건 불일치를 구분한다.

### F-12. 자동 재검색과 검수자 확인

**태그 교정·해석 교정·장면 제외 모두 검증 후 반영한다.**

1. 검수자는 변경 내용과 장면·클립 범위를 작성한다.
2. 검증을 요청하면 시스템이 원 신고의 검색어·필터를 자동으로 가져와 재검색한다.
3. 후보 태그·규칙은 그 검증 요청에만 임시 적용한다. 일반 검색과 확정 데이터는 바꾸지 않는다.
4. 검수자는 변경 요약, 영향 범위, 적용 규칙, 새로 들어온 결과·빠진 결과와 이유를 확인한다.
5. 변경안을 수정하면 다시 검증한다. 검색 실행이 성공했다는 이유만으로 자동 승인하지 않는다.

일반 검색과 검증 검색은 같은 검색 코드를 사용한다. 이미 나온 결과의 배지만 바꾸거나 재정렬하는 것으로 대신하지 않는다. 후보 태그가 후보 추출·필터·점수·설명에 모두 반영되어, 새로 검색될 장면과 제외될 장면을 계산해야 한다.

기존 규칙 R1을 R2로 교체한다면 검증할 조합은 **현재 활성 규칙 − R1 + R2**다. 태그와 해석을 함께 고치면 최종 조합으로 검증한다. 따로 성공한 두 검증만으로 조합을 확정하지 않는다.

**완료 기준:** 원 검색어·필터를 다시 입력하지 않아도 재검색된다. 검증 중 후보가 일반 검색에 노출되지 않는다. 검증 결과는 검수자용임이 표시되고 일반 검색·일반 품질 평가 집계와 구분된다. 후보가 적용되지 않거나 필요한 검증이 실패하면 확정할 수 없다.

### F-13. 교정 확정과 반영 확인

1. 검수자가 검증 결과를 확인하고 확정을 요청한다.
2. 서버는 저장된 검증 실행에서 변경안을 읽는다. 다른 변경안을 끼워 넣어 저장할 수 없다.
3. 대상 태그·근거·상속 범위·현재 처리 결과, 규칙 집합·출력 계약·검색 설정이 검증 때와 같은지 확인한다.
4. 관련 상태가 바뀌었다면 다시 검증하도록 안내한다. 전체 활성 규칙 집합 변경도 재검증 대상이다.
5. 일치하면 관련 태그 판단·규칙 교체·승인한 검증 실행 연결을 한 DB 트랜잭션으로 확정한다.
6. 검색 반영까지 확인한 뒤 신고를 종료한다.

색인 갱신이 필요한 구성에서 DB 저장만 완료된 경우에는 “교정 저장 완료, 검색 반영 중”으로 구분한다. 반영이 실패하면 검수 중 상태를 유지하고 이유와 재시도를 제공한다. 재시도는 교정 판단을 다시 만드는 것이 아니라 현재 유효 데이터로 검색 반영을 재시도하는 동작이다.

**완료 기준:** 오래된 검증으로 다른 내용을 확정하지 못한다. 동시 검수·버튼 재클릭·응답 유실 후 재요청이 교정을 중복 생성하지 않는다. 확정 실패 시 이전 확정 상태를 유지하고 완료로 안내하지 않는다. 외부 색인 실패는 DB 확정 취소와 구분한다.

검수자 확인이나 AI 호출을 기다리는 동안 DB를 잠그지 않는다. 필요한 대상 비교와 확정만 짧게 보호한다. 별도 잠금·승인 관리 테이블이나 범용 변경 영향 분석기는 추가하지 않는다.

## 6. 공통 상태, 실패와 보호 규칙

### 6.1 상태 표시

| 대상 | 저장 상태 | 화면 의미 |
| --- | --- | --- |
| 처리 작업 | `queued / running / succeeded / failed` | 대기 / 처리 중 / 처리 성공 / 실패 |
| 검색 실행 | `running / succeeded / degraded / failed` | 검색 중 / 성공 / 일부 기능 누락 / 실패 |
| 신고 | `open / reviewing / closed` | 접수 / 검수 중 / 종료 |
| 일반 태그 근거 | `verified / unverified` | 출처·근거 정책 충족 / 미검증 |
| 사람의 태그 판단 | `verified / rejected / withdrawn` | 승인 / 해당 태깅 반려 / 해당 범위 개입 해제 |
| 규칙 사용 여부 | `active` | 일반 검색에 사용 가능한 승인 규칙인지 여부 |

신고의 “종료”와 “수정 완료”는 같지 않다. `no_action`·`deferred`로 종료될 수도 있으므로 처리 결과와 이유를 함께 표시한다. 교정 검증·반영 대기는 `reviewing` 안에서 안내하며 새 상태 값을 만들지 않는다.

영상의 검색 가능 여부는 현재 제공 중인 `active_pipeline_run_id`와 논리 삭제 여부로 판단한다. 포인터는 검색 준비를 마친 처리에만 연결한다. 최신 처리의 실패와 기존 검색 제공 가능 여부를 섞지 않는다.

### F-14. 재처리와 복구

| 상황 | 처리 |
| --- | --- |
| 기존 검색 가능 영상의 재처리 | 새 처리를 실행하되 준비 전까지 기존 결과로 검색 제공 |
| 재처리 실패 | 기존 제공 결과 유지, 새 처리 실패와 재시도 안내 |
| 재처리 성공 | 준비를 확인한 뒤 현재 제공할 처리 포인터 전환 |
| 장면 재추출 | 새 장면 ID 사용. 과거 신고·결과·장면 교정을 새 장면으로 덮어쓰거나 자동 이전하지 않음 |
| 같은 원본·같은 태그 의미 | 클립 전체 교정은 유지·상속. 구 장면 예외는 새 장면으로 자동 복사하지 않음 |
| 다른 영상 원본으로 교체 | 새 클립으로 등록. 기존 클립 ID의 의미를 바꾸지 않음 |
| 규칙 문법·출력 형식 비호환 | 그 실행에서 건너뛰고 이유 기록. 검수자가 중단하거나 재검증해 교체 |

검색은 한 실행에서 사용할 처리 대상을 일관되게 정하고, 중간 전환 때문에 같은 클립의 구·신 장면을 무작위로 섞지 않는다. 과거 결과는 당시 장면과 근거를 계속 가리킨다. 다만 외부 저장소의 전체 세대를 영구 유지하는 시스템을 요구하지는 않는다.

외부·비동기 색인이 있으면 교정·재처리·재시도 모두 같은 대상의 오래된 쓰기가 최신 값을 덮어쓰지 않도록 한다. 순서가 왔을 때 현재 데이터를 읽거나 오래된 버전을 거부한다. DB에서 직접 읽는 구성에는 불필요한 외부 동기화 코드를 만들지 않는다.

중단 작업은 실패·중단 여부와 마지막 처리 상태를 확인해 명시적으로 재시도할 수 있어야 한다. 무한 재시도하지 않는다. 권한·외부 전송 거부 같은 영구 오류와 일시 오류를 구분한다. 별도 자동 복구 플랫폼·모든 장애의 무중단 복구를 약속하지 않는다.

**완료 기준:** 재처리 실패가 기존 검색을 끊지 않는다. 과거 장면 제외가 새 장면에 자동 적용되지 않는다. 유효한 클립 교정은 단순 재처리만으로 사라지지 않는다. 외부 색인을 쓰면 늦게 끝난 이전 갱신이 최신 교정을 덮어쓰지 않는다.

### 6.2 실패 시 동작

| 실패 | 사용자에게 제공할 동작 |
| --- | --- |
| AI 해석 실패·시간 초과 | 원 검색어의 단어 검색으로 전환하고 일부 기능 누락 안내. 동기 AI 재시도 없음 |
| 텍스트 의미 검색 실패 | 단어 검색과 사용 가능한 신호로 결과 제공, 누락 안내 |
| 활성 규칙 조회 실패 | 사람의 결정을 조용히 건너뛰지 않고 검색 실패·재시도 안내 |
| 기본 단어 검색도 불가 | 검색 실패. 정상적인 0건으로 표시하지 않음 |
| 결과 계산 후 기록 저장 실패 | 계산된 결과는 미저장 상태로 제공할 수 있어야 함. 저장된 결과 ID를 만들었다고 표시하지 않고 신고·교정 비활성화 |
| 검색 실행의 최초 저장 실패 | AI 호출 전에 중단하고 재시도 안내 |
| 교정 검증 실패 | 확정 금지, 기존 일반 검색 상태 유지 |
| 검증 이후 대상·규칙 변경 | 다시 검증하도록 안내 |
| 교정 DB 확정 후 색인 실패 | 검수 중 유지, 저장 완료·반영 미완료 구분, 재시도. 조건부이며 §11 에서 색인이 정본과 같은 트랜잭션이라고 확정되어 현재 구성에서는 이 상태가 생기지 않는다 |
| 외부 AI 사용 불가 | 허용된 로컬 처리 또는 정해진 대체 검색. 불가능하면 실패·생략 이유 표시 |

기록 저장 실패 중 DB가 계속 응답하지 않으면 실행 상태 기록도 실패할 수 있다. 성공 기록이 남았다고 주장하지 않고 사용자 안내와 비밀정보 없는 운영 로그로 구분한다.

### 6.3 화면·API 공통 규칙

- 상태와 오류를 한국어로 표시하고 다음 동작을 안내한다. 색상만으로 상태를 구분하지 않는다.
- 키보드 조작, 입력 항목 이름, 포커스 표시, 긴 한국어 값의 줄바꿈·전체값 확인을 지원한다. 모션 감소 설정을 존중한다.
- 검색 중·제출 중·저장 중 상태를 구분하고 중복 요청을 막는다. 실패 시 입력과 검수 내용을 가능한 한 유지한다.
- 검색 결과 0건에는 적용 필터·해석 상태·제외 정보를 보여 준다. 기록되지 않은 수치를 임의로 만들어 표시하지 않는다.
- 서버는 역할, 대상 소속, 입력 형식, 요청의 중복·오래된 상태를 검사한다. JSON 속 ID도 실제 참조를 확인한다.
- 등록·처리 목록/상세·재시도, 검색/실행 조회, 신고/목록/상세/검수 시작, 후보 검증/확정, 규칙 중단, 영상 재생 API를 제공한다.
- 교정 확정은 검증 실행 ID를 기준으로 서버에 보존된 변경안을 사용한다. 일반 사용자는 후보 적용이나 검증 맥락을 지정할 수 없다.
- API 주소·전체 JSON 스키마·HTTP 오류 코드 목록은 API 명세에서 정한다. 성공에는 유효한 식별자·상태, 실패에는 일관된 코드·한국어 설명·요청 식별자를 제공한다.

### 6.4 권한·입력·외부 전송 보호

- 업로드 형식과 실제 파일을 검사하고 임의 파일 경로·경로 이탈을 차단한다. 영상은 ID를 통해 제공한다.
- 검색어·OCR·자막·AI 응답·신고 내용을 실행 가능한 HTML이나 스크립트로 취급하지 않는다.
- 허용한 접근 출처와 로그인 상태를 검사하고, 인증 방식에 맞는 요청 위조 방어를 적용한다. 로컬 기본 범위를 임의로 공개 서버로 넓히지 않는다.
- 원본·파생 자료를 이용할 권리, 외부 처리 허용 여부와 제공자의 보관·학습·삭제 조건을 확인하기 전에는 외부 AI로 보내지 않는다. 이 요구는 별도 정책 테이블이 없다는 이유로 제거하지 않는다.
- 영상에서 나온 프레임·음성의 전송 승인과 검색어·필터의 전송 승인을 구분한다. 검색어 전송은 영상 등록 시 허용만으로 승인되지 않는다.
- 외부 호출은 승인한 제공자·목적지·데이터 종류·크기만 허용한다. 전체 영상·전체 대사·전체 OCR의 전송 금지는 유지한다. 허용하지 않은 목적지로의 리다이렉트도 따르지 않는다.
- 비밀번호·API 키·서버 절대 경로·전체 민감 원문을 일반 로그나 응답에 노출하지 않는다. 비밀값은 별도의 안전한 실행 환경 설정으로 제공한다.
- 외부 호출 기록은 원문 대신 처리 종류·크기·승인 판단·제공자 설정 식별자·성공/실패를 남긴다. 별도 감사 DB 테이블을 새로 전제하지 않는다.
- 원본 영상·프레임·음성을 저장소나 공개 배포에 포함하지 않는다. 발표·이미지·녹화 사용도 실제 이용조건을 확인하고 출처를 표시한다.
- 외부 AI·사전 처리·사전 녹화를 사용하면 실제 사용 경로를 고지한다. 기본 외부 텔레메트리는 끄고 필요한 로컬 로그만 남긴다.

이 항목은 v2.2의 보호 요구를 쉬운 문장으로 유지한 것이다. 개별 데이터나 제공자의 실제 이용 허가를 이번 문서가 확인·승인한 것은 아니다.

### 7.2 꼭 남겨야 하는 기록

- 일반 검색과 검증 검색은 매번 새 실행을 만든다. 과거 결과를 다음 검색의 해석 캐시로 사용하지 않는다.
- 태그 원본·과거 검수 판단, 규칙 본문과 종료된 검색 결과는 소급 수정하지 않는다. 실행 중 상태 갱신과 과거 결과 변경은 구분한다.
- `resolver_output_json`은 교정 전 AI 해석, `parsed_query_json`은 실제 사용한 최종 해석이다.
- `applied_rules_json`에는 규칙 ID·본문·적용 순서·적용/건너뜀/실패와 이유를 기록한다.
- `verification_context_json`에는 검증한 태그 변경안·기준 상태·후보와 교체 대상 규칙·검증 규칙 집합을 기록한다. 일반 검색에는 후보 검증 맥락을 넣지 않는다.
- `feedback.verified_by_execution_id`는 확정 전에 확인한 같은 신고의 대표 검증 실행을 가리킨다.
- `feedback.created_rule_id`는 최종 승인 규칙이다. 태그만 교정하면 비워 둔다. 한 규칙에 여러 변경 연산을 담고, 한 검색에는 여러 신고에서 만든 규칙을 적용할 수 있다.
- `tag_evidence.source_feedback_id`로 태그 판단과 원인 신고를 연결한다. 종료된 신고의 검수자·사유를 바꿔 과거 교정의 출처를 변형하지 않는다.
- 장면 제외 기록은 보존한다. 신규 패턴 경로의 복수 적용을 첫 규칙 하나로 대신 기록하지 않는다.
- **구 `applied_rule_id` 컬럼은 제거한다.** v3.0 은 보존 대상으로 두었으나 §11 에서 활성 `pin_parse` 가 0건으로 확정되어 보존할 기록이 없다. 삭제 작업은 `S15P21A501-153`.
- 과거 `explain_json`은 당시 태그 값과 근거를 설명한다. 지금의 교정 상태로 다시 계산해 덮어쓰지 않는다.
- 처음부터 없던 과거 원본 해석·검증 맥락을 추정해 채우지 않는다.

전체 활성·비활성 사건 감사나 모든 외부 상태의 완전한 시점 복원을 보장하지 않는다. 실행 당시 기록을 조사할 수 있다는 것과 AI를 다시 실행해 언제나 같은 결과를 얻는다는 것은 다르다.

참조 중인 영상·장면·검색·신고·교정 기록을 지우는 하드 삭제 화면은 만들지 않는다. 영상의 논리 삭제를 사용하더라도 과거 참조는 보존한다. 별도 삭제 UI의 추가는 이번 문서에서 요구하지 않는다. 실제 운영 보존기간·삭제 절차는 운영 전 확정한다.

DB 제약, 조회 인덱스, JSON 스키마, 잠금 순서와 저장 트랜잭션은 구현 명세의 영역이다. ERD에 FK가 있다는 사실만으로 같은 클립·같은 신고·검증 내용 일치까지 자동 보장되지는 않는다.

### 8.1 전체 흐름 확인

| 시험 | 합격 조건 |

| 재처리 | 기존 검색 유지, 구 장면 교정 미승계, 같은 의미의 클립 교정 유지 |
| 조건부 외부 색인 | **§11 에서 해당 없음으로 확정.** 외부·별도 색인을 쓰지 않으므로 이 시험을 수행하지 않는다 |
| 조건부 구 규칙 | 실제 구 pin_parse가 있으면 호환·교체 검증. **§11 에서 0건으로 확정되어 호환 전환과 이 시험 모두 수행하지 않는다** |
| 외부 전송·입력 보호 | 미승인 자료·검색어 전송 차단, 경로 이탈·스크립트·권한 우회 차단 |
| 기록·실패 안내 | 전후 해석·검증·적용 내역 확인, 기록 미저장 결과의 신고 차단 |

각 기능의 완료 기준과 위 흐름 시험을 함께 통과해야 한다. 기능이 아니라 문서만 작성된 상태를 완료로 체크하지 않는다.

### 8.2 기존 품질 목표 유지

아래는 v2.2에서 이어받은 목표다. 현재 ERD가 충족하거나 측정됐다는 뜻은 아니다.

| 대상 | 목표·확인 내용 |
| --- | --- |
| 검색 정확도 | 상위 10개 정답 포함률([Recall@10](mailto:Recall@10))이 기존 수기 검색보다 5%p 이상 개선 목표. 순위 품질([nDCG@10](mailto:nDCG@10)·MRR) 함께 보고 |
| 잘못된 결과 | 명시 조건과 검증된 정보가 충돌한 결과의 비율과 실제 반환 수·검색 가능한 질의 비율을 함께 측정 |
| 사용자 업무 | 사용할 장면을 찾은 성공률·만족도 개선, 편집기자+검수자 총업무시간 유지 또는 감소 |
| 검색 응답 | 95% 요청이 10초 이내 목표. 일반·규칙 적용·대체 검색·후보 검증을 구분 측정 |
| 미리보기 | 첫 화면까지 95% 요청이 2초 이내 목표. 최초·반복 접근 구분 |
| 처리 속도 | 모델 준비 후 짧은 영상 분석 30초, 기존 333클립 묶음 약 2시간 목표. 장비·영상 조건 명시 |
| 추출 품질 | 샷 유형 Macro F1 0.80 이상, 설명 정확·부분 정확 85% 이상, 음성인식 WER 40% 이하 목표 |
| 교정 효과 | 원 사례 개선, 다른 표현·다른 질의의 적용 범위, 기존 정상 검색의 회귀 여부 확인 |

수치·장비·표본을 임의로 새로 만들지 않는다. 속도·추출 지표 하나만으로 제품 전체가 성공했다고 판단하지 않는다. ASR 품질이 목표에 못 미치면 해당 신호 영향 조정을 개발셋에서 검토·측정하고 검색 설정 변경을 기록한다. 높은 ASR 신뢰도로 verified로 올리는 규칙과는 구분한다.

### 8.3 평가가 왜곡되지 않도록 할 일

- 같은 영상·중복 영상·같은 원천 뉴스 묶음이 개발셋과 최종셋에 갈라지지 않도록 한다. 기존 6:4 분리 원칙을 유지한다.
- 모델·규칙·순위 설정은 개발셋으로 조정하고, 최종 평가셋의 정답을 검색 입력이나 교정 데이터로 쓰지 않는다.
- 일반 검색 평가와 교정 후 개선 평가를 나눈다. 일반 평가에는 개발 중 만든 태그 교정·해석/제외 규칙이 섞이지 않도록 평가 데이터 상태를 고정한다.
- 수기 검색과 제공 자막·음성인식·설명·OCR·의미 검색·해석·제외 기능을 단계적으로 비교한다. 다른 표본의 원시 수치를 직접 우열로 비교하지 않는다.
- 결과를 적게 반환해 오류율이 낮아 보이게 하지 않는다. 반환 결과가 전혀 없으면 오류율을 0이 아니라 측정 불가로 보고한다.
- 사건 충돌 판정 규칙이 승인되지 않았다면 해당 자동 제외를 끄고 그 지표를 측정 불가로 구분한다.
- 사용자 평가는 같은 과제를 비교하고 작업 순서 효과를 통제한다. 재검색 시간과 사람이 확인·교정한 시간을 모두 포함한다.
- 기존 데이터 기본안(333클립·약 2,200장면), 장면 정답 100개 이상·검색 질의 30개 이상, 별도 범용성 확인 20~30클립은 평가 계획의 기준으로 유지한다. 확보된 실제 규모·교차 검수·장비·설정·원시 결과를 보고한다.
- 데이터 분할·판정 기준·허용 결과 범위·평가 척도와 유의미한 개선 기준은 최종 평가셋을 보기 전에 확정한다.

상세 계산식·비교 실험 구성은 v2.2 §14를 참고하되, “해석 규칙은 항상 AI 미호출”, “유사 표현에는 항상 미적용”, “태그 교정은 무조건 보류”라는 기존 시험은 이 문서의 새 교정 시험으로 대체한다.

| DEC/Gate, §15 | §9~10 | 과거 결정 이력으로 보존. 새 범위의 확정 근거와 미정 항목 분리 |
| 구현 체크리스트·한계, §16 | §1.2, §8~9 | 옛 주차별 구현 계획을 완료 증거로 사용하지 않음 |

### 10.3 참고 자료와 검증 범위

- `N-Pick-PRD-v6`: 짝을 이루는 제품 기준본. Gate 명칭의 대응은 PRD §0.2 참고.
- `N-Pick-ERD-v3.1`: 표·컬럼·관계의 정본 설명 문서.
- 「후보 검증 검색 구현 방식 — 트랜잭션 롤백」: §11 후보 검증 결정의 근거.
- 기존 FRD v2.2: 유지 기능·예외·품질 목표의 근거. 원본 파일은 수정하지 않는다.
- [현재 ERDCloud](https://www.erdcloud.com/d/eFoaB2wCwPcCZFNzX): 2026-09-04 재조회한 컬럼·관계·주석 기준.
- 피드백 루프 최종 설계안: 후보 검증, 태그 우선순위, 규칙 문법·충돌, 저장·색인 상세.
- ERDCloud 반영 결과: 컬럼 6개·FK 1개와 주석 반영 확인. 최종 설계안 머리말의 작성 당시 “미적용” 상태는 이 후속 기록으로 구분한다.
- 관계·배치 검증 결과: 관계 검증과 위치 변경 기록.

이번 문서의 확인 범위는 v2.2와 현재 ERD·교정 설계의 기능 정합성이다. 실제 DB 제약, API, 검색 정확도·속도·동시성 테스트는 수행하지 않았다. 이 FRD 의 정본은 Notion 이고 저장소 `docs/frd/` 반입은 `S15P21A501-154` 다. 작성만으로 DB·코드·ERD가 추가 변경되지는 않는다.

| 구 규칙·외부 색인 | **둘 다 없음 — 닫힘** | 활성 `pin_parse` 규칙이 0건이다 (검색 코드가 한 번도 실행되지 않았고 baseline 마이그레이션도 적용된 적이 없다) → 호환 경로·전환 작업을 만들지 않는다. 외부·비동기 색인은 사용하지 않는다 (`docs/architecture/02-container.md`, PoC 실측 근거 포함) → outbox·오래된 쓰기 차단·reconciliation job 을 만들지 않는다 |

**복원과 확정 반영은 다르다.** F-03 의 요구는 v3.2 가 새로 만든 것이 아니라 v3.1 재작성에서 빠진 것이다. v3.1 은 §11.2 에서 「기능 범위가 줄어든 것은 군중 밀도 하나다」라고 선언했는데, 장 수를 내용으로 정한다는 요구의 폐기는 그 목록에도 §11 확정 8건에도 §11.1 미결 3건에도 없다. 결정된 적도 미결로 잡힌 적도 없으므로 폐기가 아니라 누락이다. 사라진 원문은 `581f6e3` 에 있다.

나머지 2건은 v3.1 이후 코드·설계에서 확정됐는데 문서에 반영되지 않은 것이다. 없던 요구를 새로 만든 것이 아니다.

문서를 다시 쓸 때 **분량을 줄인 것과 요구를 잃은 것을 구분한다.** 범위를 줄이지 않았다고 적은 개정에서 요구가 사라졌다면 분량 문제가 아니라 범위 문제다. 다음 재작성에서는 §11.2·§11.4 의 변경표를 근거로 기능 목록을 대조한다.
