# 0001. App Router와 기능 단위 경계 사용

- 상태: Accepted
- 날짜: 2026-09-01
- 대체: 없음

## 배경

NewsCut 프론트엔드는 검색 editor 화면과 처리·문의 reviewer 화면을 제공해야 합니다. route 구성, 기능 전용 코드, 공통 UI와 API 기반 코드가 한 디렉터리에 섞이면 기능이 늘어날수록 책임과 재사용 범위를 판단하기 어려워집니다. 한편 초기 단계부터 세분화된 계층과 빈 디렉터리를 만들면 실제 요구보다 구조가 앞서 복잡해질 수 있습니다.

## 결정

- Next.js App Router를 route와 layout 경계로 사용합니다.
- `src/app`은 route와 화면 조합을 담당합니다.
- 기능 전용 UI와 로직은 `src/features/<feature>`에 둡니다.
- 여러 기능에서 공유하거나 앱 전역에 사용하는 UI는 `src/components`에 둡니다.
- 환경변수와 HTTP client 같은 공통 기반 코드는 `src/lib`에 둡니다.
- Server Component를 기본으로 사용하고 필요한 최소 상호작용 경계만 Client Component로 만듭니다.
- feature 내부 하위 디렉터리는 실제 코드가 필요할 때 추가합니다.

## 이유

App Router의 파일 규약을 그대로 활용하면서 route와 기능 구현의 책임을 분리할 수 있습니다. 기능 단위 배치는 검색과 검수 기능의 변경 범위를 좁히고, 공유가 확인된 코드만 공통 계층으로 이동하게 해 불필요한 추상화를 줄입니다.

## 영향

- route 파일은 얇게 유지하고 기능 구현을 직접 소유하지 않습니다.
- feature는 다른 feature의 내부 코드를 직접 import하지 않습니다.
- 공통화하려면 코드의 재사용 범위와 책임을 먼저 확인해야 합니다.
- Client Component 경계를 추가할 때 브라우저로 전송되는 코드와 직렬화 가능한 Props를 고려해야 합니다.
- 계층 책임이나 의존 방향을 바꾸려면 새 ADR로 이 결정을 대체해야 합니다.
