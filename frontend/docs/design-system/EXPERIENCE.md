# N-Pick Glass — Experience Spine

## Foundation

단일 responsive web 표면이며 Next.js, React, Tailwind CSS와 CSS Module을 사용한다. 시각 정본은 `DESIGN.md`다. 이 문서는 글래스 로그인 모듈의 행동, 상태, 접근성과 흐름을 소유한다. 구현 화면이나 시안과 충돌하면 두 정본 문서가 우선한다.

## Information Architecture

| Surface              | Reached from                   | Purpose                               |
| -------------------- | ------------------------------ | ------------------------------------- |
| 역할 선택 `/landing` | 공개 진입                      | 편집기자 또는 검수자 로그인 흐름 선택 |
| 로그인 `/login`      | 역할 선택, 인증 만료, 로그아웃 | 자격 증명 입력과 안전한 세션 시작     |
| 검색 `/search`       | 편집기자 로그인 성공           | 편집기자 기본 작업 진입               |
| 검수 `/review`       | 검수자 로그인 성공             | 검수자 기본 작업 진입                 |

로그인 화면에는 중앙의 주 글래스 모듈 하나만 둔다. 별도의 왼쪽 환영 문구와 장식용 scene art는 사용하지 않는다.

## Voice and Tone

브랜드 시각 언어는 `DESIGN.md`의 Brand & Style을 따른다. 로그인 문구는 짧고 업무 중심으로 작성한다.

| Do                                               | Don't                          |
| ------------------------------------------------ | ------------------------------ |
| `편집자님, 반가워요.`                            | 과도한 환영 문구나 마케팅 카피 |
| `ID와 비밀번호를 입력하고 작업을 시작하세요.`    | 기능과 무관한 슬로건           |
| `로그아웃 되었습니다.`                           | 굵은 성공 선언이나 느낌표      |
| `로그인이 만료되었습니다. 다시 로그인해 주세요.` | 원인을 숨기는 일반 오류 문구   |

## Component Patterns

| Component            | Use             | Behavioral rules                                                                                      |
| -------------------- | --------------- | ----------------------------------------------------------------------------------------------------- |
| Login glass panel    | 로그인 화면     | 화면 주 작업 영역 중앙에 하나만 배치한다. 시각값은 `DESIGN.md.Components.login-glass-panel`을 따른다. |
| Back link            | 패널 첫 행      | `/landing`으로 돌아간다. 제목 행과 15px 간격을 유지한다.                                              |
| Login heading        | 패널 제목       | 역할별 아이콘과 `로그인`을 같은 행에 둔다.                                                            |
| Credential field     | 아이디·비밀번호 | 항상 외부 라벨을 제공한다. 아이콘은 장식이며 실제 input의 accessible name은 라벨이 제공한다.          |
| Primary login action | 폼 제출         | 제출 중 중복 요청을 막고 `로그인 중…`으로 상태를 바꾼다.                                              |
| Success glass toast  | 로그아웃 복귀   | 패널 밖 화면 상단 중앙에 나타나며 다른 조작을 막지 않는다. 3초 뒤 제거한다.                           |

## State Patterns

| State               | Treatment                                                                                           |
| ------------------- | --------------------------------------------------------------------------------------------------- |
| Default             | 입력값이 비어 있고 로그인 버튼을 사용할 수 있다.                                                    |
| Focus               | 선택한 입력 컨테이너에 `{colors.accent}` 계열 포커스 테두리와 링을 표시한다.                        |
| Empty submit        | 해당 필드 아래에 한국어 오류를 표시하고 첫 오류 입력창으로 포커스를 옮긴다.                         |
| Invalid credentials | 패널에 오류 상태를 표시하고 버튼을 잠시 비활성화한다. 사용자가 입력을 수정하면 다시 시도할 수 있다. |
| Submitting          | 중복 제출을 차단하고 버튼 문구를 `로그인 중…`으로 바꾼다.                                           |
| Session expired     | 패널 내부에 재로그인이 필요하다는 상태 문구를 표시한다.                                             |
| Logged out          | 패널 내부에는 성공 문구를 넣지 않는다. 상단 success glass toast를 3초간 표시한다.                   |
| Reduced motion      | 흔들림과 토스트 이동·페이드 애니메이션을 제거하되 상태 변화와 3초 제거 동작은 유지한다.             |

## Interaction Primitives

- Tab 순서는 역할 다시 선택 → 아이디 → 비밀번호 → 로그인이다.
- Enter로 폼을 제출할 수 있다.
- 아이디는 `autocomplete="username"`, 비밀번호는 `autocomplete="current-password"`를 유지한다.
- 제출 직전 공백 아이디와 빈 비밀번호를 검증한다.
- 로그인 성공 후 역할과 허용된 내부 복귀 주소에 따라 전체 문서 이동을 수행한다.
- 비밀번호는 요청 완료 후 DOM 입력값에서 제거한다.
- 로그아웃 성공 알림은 자동으로 사라지는 비차단성 상태다. 닫기 버튼이나 사용자 확인을 요구하지 않는다.

## Accessibility Floor

- 모든 입력에는 화면에 보이는 `label`과 고유한 `id`가 있어야 한다.
- 오류 입력은 `aria-invalid`와 `aria-describedby`로 오류 문구에 연결한다.
- 비동기 제출 상태와 오류는 live region으로 전달한다.
- 로그아웃 토스트는 `role="status"`와 `aria-atomic="true"`를 사용해 한 문장으로 읽힌다.
- 오류·성공·포커스를 색상만으로 전달하지 않는다. 문구 또는 명확한 포커스 위치를 함께 제공한다.
- 키보드 visible focus를 유지한다.
- `prefers-reduced-motion: reduce`에서는 필수 상태 변경을 제외한 이동 애니메이션을 제거한다.

## Responsive & Platform

| Breakpoint | Behavior                                           |
| ---------- | -------------------------------------------------- |
| `> 1100px` | 최대 470px 패널, `32px 40px 28px` 내부 여백        |
| `≤ 1100px` | 패널 내부 여백을 30px로 단순화                     |
| `≤ 850px`  | 좌우 화면 여백 20px 이상, 모듈 바깥 하단 공간 32px |

최신 Chrome을 기준으로 하되 키보드와 자동완성의 웹 표준 동작을 유지한다. 자동완성 시 브라우저 고유 배경이 글래스 표면과 충돌할 수 있으므로 시각 보정은 허용하지만 자동완성 자체를 비활성화하지 않는다.

## Key Flows

### Flow 1 — 편집기자의 로그인

1. 편집기자가 역할 선택에서 편집자 로그인을 선택한다.
2. 중앙 글래스 모듈에서 아이디와 비밀번호를 입력한다.
3. 로그인 버튼 또는 Enter로 제출한다.
4. 시스템은 제출 중 중복 요청을 막고 계정을 확인한다.
5. **Climax:** 성공한 실제 역할이 편집기자이면 검색 화면으로 이동해 작업을 시작한다.

실패 시 민감 정보를 노출하지 않는 한국어 오류를 표시하고, 입력을 수정해 다시 제출할 수 있게 한다.

### Flow 2 — 로그인 사용자의 로그아웃

1. 로그인 사용자가 제품 헤더에서 로그아웃을 실행한다.
2. 서버 로그아웃 성공 뒤 세션 캐시와 앱 소유 초안을 정리한다.
3. 전체 문서 이동으로 로그인 화면에 돌아온다.
4. **Climax:** 로그인 패널 밖 상단 중앙에 `로그아웃 되었습니다.` 글래스 토스트가 나타난다.
5. 토스트는 약 3초 후 사라지고 로그인 모듈만 남는다.

로그아웃 API가 실패하면 성공 토스트를 표시하거나 로그인 화면으로 성공 이동한 것처럼 처리하지 않는다.
